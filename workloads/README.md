# 公開側で実行する3分野

`gan-stat-app/municipal-smr-site` の2026-10-29時点の選択コードを、履歴を移さず `snapshot/` に保存します。`inputs.json` に元コミット、コードのGit blob、公開データのGit blobを固定します。ウェブサイトの運営・公開先はmunicipal-smr.jpのままです。

本番配信時のHTML等の変換に依存しないよう、公開許可済みのHTML・JavaScript・CSS・SVG等287ファイルもGit原本と同じバイトで同梱します。データの取得・照合を緩める変更ではありません。週次ビルドは月曜03:00 JSTに公開側で実行し、非公開側の04:00検証より先に証跡を用意します。

## 実行対象

1. `opendata.py`: 全国76資料と秋田ポータルの公開済み一覧を読み、公式URLの原本を取得し、固定版HarunobuをAIなしで実行します。独立した減点計算でも得点を確認します。原本・シート名・セル証拠・詳細な指摘は一時領域内だけに置き、外へ出すのはID・ハッシュ・処理状態・数値得点だけです。初回の自動受入実行は12資料で、`workflow_dispatch` の `opendata_limit=0` では全件を指定できます。12資料の成功を全件再検査の成功とは扱いません。
2. `site.py`: 公開資産3,230件を元Git blobと照合し、公開ミラーを復元します。既存の `npm ci`、依存脆弱性検査、`npm run build`、`npm test`、記事一覧・地図・二次医療圏・死亡差・DPC・学校保健の画面検証、生成バンドル検査を実行します。生成したアプリ資産と証跡だけを7日保存し、全チェックアウトや取得原本は保存しません。
3. `collectors.py`: 既存の公式取得器・正規化コードを用い、施設基準は毎月16・26日06:37 JST、食品営業は20日08:17 JSTに実行します。元と同じ頻度です。初回pushは各1取得先の受入検査、定期・手動のlimit=0は全取得先です。原本は一時領域、ハッシュと出典は証跡、正規化済み公開項目は14日間の成果物へ保存します。申請者名・自宅住所・電話番号を食品営業の正規化項目へ追加しません。未確認の違反指摘や記事を自動公開しません。

東北の項番7は `tohoku.py` と専用の既存時刻（毎月16日06:17 JST）の公開ワークフローで6県を取得します。食中毒の既存テストが読む `source/food-poisoning/` は、元のHTML・JS・CSSと公開済みデータの同一バイトで復元します。本番用の別版と取り違えません。

## 安全性と反映

公開側に非公開リポジトリを読めるトークンを登録しません。計算ジョブは読取権限、Actionは固定SHA、PRでは軽量なセキュリティ・契約テストだけを実行します。mainの独立したpublishジョブだけが、この公開repoのcontents:writeを使い、許可したアプリ資産・正規化データ・証跡のZIPを公開Releaseへ渡します。原本・詳細指摘・未知のパスは拒否します。利用側はGitHub artifactのdigestと同じバイトだけを採用し、別repoを読む秘密鍵を追加しません。重い処理はmainへのレビュー済み変更・手動・既存の月次時刻で実行します。エラー・非対応形式・取得失敗を0件や100点へ変換しません。

現在の公式原本と、保存済みの過去原本は別です。公式URLの内容が変わった場合は変更として記録し、過去原本が復元できたとは扱いません。非公開の保存原本、全記事の独立した数値検査、公開境界、本番配信確認は必要に応じて非公開側に残します。

`reports/*.json` は元コミットと入力一覧のSHA-256を持ちます。非公開側は、公開mainの成功した実行、期待ワークフロー、実際のジョブ成功、元コードとデータの一致を照合した場合だけ対応する結果を再利用します。入力不一致・失敗・証跡不足・期限切れでは省略しません。記事・データの内容が変わった場合に、古い成功結果だけで公開してはいけません。

収集成果物の取り込みは、公開側の固定コミット・run ID・ファイルハッシュを確認してから、施設・食品・東北それぞれの既存レビュー担当へ渡します。各担当の実行日・公開権限を変更しません。公開記録10ファイルの18時同期とは別です。必要な保存原本は非公開側で公式URLから取得し、公開証跡と同一ハッシュであることを確認して保管します。取得不能なら原本保存未完了として保留します。公開側の正規化結果だけで保存済みと記録しません。

移行後はこの3分野のコードをまず公開側のsnapshotと入力一覧へ同時反映し、公開CI成功後に非公開側へ採用します。非公開側のコードや入力が先に変わった場合は、公開側を更新するまで通常の検証を維持します。原本を公開するために `.assetsignore` を広げる必要はありません。
